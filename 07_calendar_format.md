# Calendar Format — `1_1c_calendar.yml`

Forward-looking topic calendar. The `mpd-producer` skill resolves an
episode's metadata from this file when given a `D###` reference.

## Schema

```yaml
year: 2026
year_window: 2026-05-01 to 2027-04-30
generated: '2026-04-30'
generator_version: mpd-calendar-builder v1.0
notes: |
  Manual overrides take precedence. To skip a date, set status: skipped.
  To freeze a date against rebuild, set frozen: true.

entries:
  - date: 2026-05-01           # ISO date
    week: "D001"                # 3-digit day number with D prefix
    topic_short: "PayYourselfWrong"   # PascalCase, ≤16 chars
    topic: "Why 'Pay Yourself First' Doesn't Work for Most People"
    pillar: P1                  # P1–P5
    keyword: "pay yourself first not working"
    relevance_window: "Wedding / vacation prep"
    status: queued              # queued | in_progress | shipped | skipped
    frozen: false               # true = exclude from calendar regeneration
    source_notes: ""            # path to research notes (relative to workspace)
    notes: "auto-suggested — review before filming"
```

## Status values

| Status | Meaning |
|---|---|
| `queued` | Default. Available for production. |
| `in_progress` | Active episode (currently being produced). Should match `queue.yml` active entry. |
| `shipped` | Published to YouTube. Frozen. |
| `skipped` | Date passed without production. Recorded for cadence-tracking. |

## Producer skill behavior

When user invokes "Run stage 3.X for D012":

1. Producer `web_fetch`es `1_1c_calendar.yml`.
2. Finds entry where `week == "D012"`.
3. Extracts `topic_short`, `topic`, `pillar`, `keyword`, `relevance_window`,
   `source_notes` as input parameters.
4. Falls back to `queue.yml` if D012 not in calendar.
5. If neither has it, asks user for missing fields.

## Active queue (`queue.yml`)

A separate, smaller file in this repo tracks the currently-active episode.
Updated manually (or by user via mpd-patch) when starting a new episode.
See [queue.yml](queue.yml).

## Pruning the auto-variants

The current `1_1c_calendar.yml` was generated by mpd-calendar-builder to fill
365 days. Beyond W46 of the corpus, entries are auto-generated variants like
"FakeDiversify6", "MortgServ4", etc. — these are placeholder titles that need
replacing with real topics before production. Recommend pruning the calendar
to ~50 real topics for v1.3 (3 eps/week × ~17 weeks coverage).

## Refresh protocol

The `mpd-calendar-builder` skill is being retired in v1.3 (one-shot, run once,
delete). Manual edits to `1_1c_calendar.yml` are the new norm. To refresh:

1. Edit YAML directly (any text editor).
2. Bump `generated` date.
3. Bump `generator_version` to `manual-edit-YYYYMMDD`.
4. `git push`.
